# 界面微文案规范 (UX Copy) — 撰写或优化按钮 CTA、空状态、报错信息与确认弹窗文案
> 来源：`C:\Users\18791\.codebuddy\plugins\marketplaces\cb_teams_marketplace\plugins\design-to-code\skills\ux-copy\SKILL.md`

Write or review UX copy — microcopy, error messages, empty states, CTAs, and confirmation dialogs.

## Core Principles

1. **Clear**: Say exactly what you mean. No technical jargon, no ambiguity.
2. **Concise**: Use the fewest words that convey the full meaning.
3. **Consistent**: Use the exact same term for the same concept everywhere.
4. **Useful**: Every word should help the user decide or act.
5. **Human**: Write like a helpful colleague, not a system log.

## Copy Patterns

### CTAs (Buttons)
- Start with a concrete verb: "保存更改" / "导出记录" / "让经理继续" (avoid vague "提交" / "确定").
- Match the button label to its real outcome.

### Error Messages
Structure: **What happened + Why + How to fix**
- Example: "模型服务认证失败（HTTP 401），请在「设置 → 模型服务」中检查 API 密钥。"

### Empty States
Structure: **What this area is + Why it's empty + How to start**
- Example: "还没有群聊。点击「新建群聊」拉入参会成员即可开始。"

### Confirmation Dialogs
- State the exact target and action: "删除「方案评审」的聊天记录？" (never just "确定吗？")
- State consequences clearly: "此操作无法撤销，本地已保存的文件会保留。"
- Label buttons with explicit actions: "删除会话" / "取消" (not "OK / Cancel").

### Voice & Tone by Context
- **Success**: Crisp and reassuring, never over-the-top.
- **Error**: Empathetic, calm, actionable.
- **Warning**: Clear on risk and next step.
- **Loading / Status**: Honest progress, avoid robotic filler.
