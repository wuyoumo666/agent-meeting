## 0. 先做「Design Read」再写代码
动笔前先用一句话定调：**页面类型 + 目标受众 + 视觉调性 + 依托的设计体系/美学家族**。
- 明确要「极简克制 / Linear 风 / 杂志编辑风 / 专业 B2B 工具 / 实验性创意」，不要套默认紫色渐变 + 居中 Hero + 三张均等卡片。
- 若遇到已有项目改版（Redesign），先审计现有品牌色、字体与可用结构，在此基础上做减法与重整。

## 1. 三项核心调节旋钮（按场景设定）
- **DESIGN_VARIANCE (1-10)**：版式变化度（极简/高信任产品 3-6；营销着陆页/创意作品集 7-9）。
- **MOTION_INTENSITY (1-10)**：动效强度（后台/工具类 2-4；展示/品牌页 6-8）。
- **VISUAL_DENSITY (1-10)**：信息密度（留白画廊风 2-3；桌面工具/驾驶舱 5-8）。

## 2. House Rules（版式与去噪铁律）
1. **标题不超过两行**：在所有宽度下控制标题字数与行宽，避免多行折行破坏视觉锚点。
2. **克制装饰性元素**：
   - 禁用“小圆角卡片 + 左侧彩色竖条”的 AI 常见模板；
   - 禁用无意义的眉标（Eyebrow pill）、序号编号（`01 / 02 / 03`）和假指标卡片；
   - 禁用 emoji 当图标、头像或占位符，统一使用单线 SVG 图标（统一 `strokeWidth` 如 `1.5` 或 `1.65`）且全项目只用同一套图标风格；
   - 静态元素少用重阴影和霓虹光晕，优先用**轻微的明暗色调阶梯（Tonal steps）**区分表面层级，阴影留给真正浮起的弹窗和菜单。
3. **字体与字阶对比**：
   - 全页字体不超过 2 种，字号档位控制在 4-5 档内，正文保持 14-18px、行高 1.45-1.65、每行约 45-75 字符；
   - `monospace` 只用于真实代码块、命令和等宽数字（金额/计时用 `tabular-nums`）。
4. **色彩纪律**：
   - **One ground, one ink, one accent**：清晰的主背景、高对比正文墨色（避免全篇弱灰字显得像未完成稿）、一个主强调色用在核心操作上；
   - 禁用默认 Tailwind indigo/violet 双色渐变英雄区。
5. **网格与对齐**：
   - 使用 CSS Grid 替代复杂 flex 百分比计算；全页共享清晰的左对齐基准线，留白要有节奏（区块间距明显大于内部元素间距）；
   - 全屏容器使用 `min-height: 100dvh` 避免移动端跳动。

## 3. 设计体系与技术选型原则
- **需要正式设计系统时**（企业后台/工具），优先尊重项目已有技术栈与组件库，不混用两套设计体系（如同时混 Fluent 与 Material）。
- **React/动效注意**：切勿用 `useState` 追踪鼠标坐标或滚动进度等高频连续值；尊重 `prefers-reduced-motion`。
- **代码前校验依赖**：引入任何第三方库前先核对 `package.json`，不凭记忆编造包或接口。
